# クリーン導入・制作・サイト操作の検証

確認日：2026-10-21。macOS / Node.js 24 / Git / Codex CLI 0.163.0-alpha.10.2。

## 2行導入から実際のアプリへ

新しいCodex設定領域と空の作業フォルダを使い、公開リポジトリから2行の導入を実行。既存のユーザー設定、MCP、作者のスキル、作業記憶は引き継いでいない。認証には既存の本人ログインを利用した。

| 段階 | 確認結果 |
| --- | --- |
| marketplaceの追加とpluginの導入 | 2行ともexit 0 |
| 導入したスキルから100選を取得 | 100件一覧と006の取得に成功 |
| 実際のCodexによる生成 | 006「動画チャプター下書き」を空フォルダで生成、exit 0 |
| 関数の試験 | 4件合格。時刻境界、不正順序、保存復元、破損データなど |
| 通常のターミナルから起動 | `node server.mjs` でHTTP配信に成功 |
| 初期化と入力 | 初期のscript入口で初期化が止まる事象を発見。HTMLを既存のES module入口へ揃えて再確認 |
| 章の追加と検証 | 3章を入力。逆順・重複の警告と書き出し無効を実画面で確認 |
| 並べ替えとコピー | `00:00 はじめに / 00:59 準備 / 01:00 本編` をコピー |
| 再読込 | プロジェクト名・3章・出力が復元 |
| 動画 | 75秒の合成動画を読込、59秒へ移動・再生・現在時刻から章を追加 |
| ファイル出力と復元 | txt・JSONをダウンロードして内容照合。JSONから作業を復元 |

Codexの実行制限下でlocalhostの待受が `EPERM`、ブラウザの直接起動も失敗した。スキルに「環境制限とコードの障害を分け、許可されたプレビューへ引き継ぐ」「実際に配信するHTMLとスクリプト入口で検証する」という案内を追加した。

## v0.2.0の公開ランチャー経路

別の空のCodex設定領域で公開2行を実行し、0.2.0を取得。100件一覧から100を選び、次の公開パッケージを取得して実際のCodexを起動した。

```sh
npx --yes --package github:fuuuuuuma/app-forge#v0.2.0 app-forge start 100 --agent codex --exec --out ./app-100
```

npx・ランチャー・Codexはexit 0。追加の依頼文や評価担当による実装補助は使っていない。生成された「ことのは Desk」は4件の試験に合格。今回は制限されたサーバー起動後に未検証の別入口を足さず、通常ターミナルでの確認手順を残せた。

通常ターミナルで `npm start` を実行し、ブラウザで以下を確認した。

- アプリ名・対象者・機能追加、実装済み/予定の切り替え。
- 予定機能を含まない下書き、実装済みに変更した後の反映。
- 絵文字を含むタイトルの文字数、強い表現の警告。
- 再読込後のタイトル・内部メモの復元。
- 公開用txtを実際にダウンロードし、内部メモと予定機能を含まないことを照合。

0.2.0は通常の対話CLI起動も備える。この通し試験は非対話の `--exec` 経路を使った。承認回避のフラグや追加の有料サービスは使っていない。

## 限界

Webの2案を実際に生成した試験であり、100案すべての完成や全環境の互換性を示すものではない。Windows/Linux実機、iOS/Android実機、App Store・Google Playへの実提出、Claude Code本体による生成は未検証。モバイル画面はブラウザの375px表示で検証し、指のタッチ操作を実機で確認したものではない。
