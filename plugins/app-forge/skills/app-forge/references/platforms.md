# 構成を選ぶとき

作る対象、利用者の端末、持っている環境から決める。既存アプリの改修なら既存スタックが第一候補。流行の技術へ移すこと自体を成果にしない。

## Web / PWA

個人用ツールはブラウザ保存で始められる。永続性が必要ならJSON/CSVの書き出しと取り込みも付ける。複数端末・チーム共有にはサーバー保存と認証が必要。PWAはURL配布とホーム画面追加に向くが、OSのバックグラウンド動作や通知は対象端末で確認する。

Sitesが利用可能なら、紹介サイトや小さなWebツールを会話から作って公開する選択肢として案内する。ツールと専用スキルがある場合はその手順に従う。視聴者側にSitesがなければ、静的ホスティングや既存の配備先で進められる。Sites利用を前提に手順を止めない。

Cloudflareは静的アセット/WorkersのAPI、D1の構造化データ、R2のファイル保存を分けて考える候補。R2を使っても転送・リクエスト・周辺サービスまで常に無料とは言えない。採用前に現在の[制限](https://developers.cloudflare.com/workers/platform/limits/)と[料金](https://developers.cloudflare.com/workers/platform/pricing/)を確認する。動画変換など長いCPU処理は実測し、端末や専用処理基盤との役割を決める。

## モバイル

両OS向けの一般的な画面ならExpo/React Nativeを候補にする。独自のネイティブSDK・深いOS連携が中心ならdevelopment build、Swift/Kotlin/Flutterも比較する。Expo Goで動くこととストア用アプリで動くことは別に確認する。OS固有の通知・カメラ・共有・購入は実機で通す。

## Chrome拡張

Manifest V3を使い、`activeTab`など必要時の権限で足りるか先に検討する。対象サイトが決まっているならhost permissionsを絞る。service workerは停止・再開する前提で状態を保存する。SPAの画面切替・DOM変更・ボタン重複挿入を試す。外部連携では送信先と送る情報を表示する。AIや外部APIの共通秘密鍵は拡張に埋めずバックエンドに置く。[公開手順](https://developer.chrome.com/docs/webstore/publish)。

## 認証・共有・AI

- APIの各リクエストで本人と対象データへの権限を確認する。UIで隠すだけにしない。別ユーザーA/Bで読取・更新・削除を試す。
- OAuthの同意画面、redirect URI、本番と開発の認証設定を揃える。汎用の別製品名が出たまま配らない。
- 外部AIへの入力は必要な部分だけにする。秘密鍵はサーバー環境変数、ブラウザには返さない。サイズ制限・タイムアウト・再試行・費用上限を決める。通信失敗時に入力を失わない。
- TypeSafeは分類やランキング等の型付き判断が必要なときの候補。確率を正解の保証とみなさず、入力・出力スキーマ・不確実な場合の動作をコード側で決める。採用時は[公式スキル](https://github.com/typesafe-ai/skills)と現行ドキュメントを確認する。通常のCRUDまでAIで置き換えない。

## Codex App Server

自作UIからCodexのスレッド、ターン、進捗や承認を扱いたいときに検討する。まずインストール済みの `codex app-server --help` と[公式資料](https://developers.openai.com/codex/app-server/)を確認し、現在の初期化・認証・イベント・承認の仕様に合わせる。stdio等のローカル接続から検証し、サービス公開のためにローカルの開発権限をそのままインターネットへ露出させない。

利用者の明示操作で開発を開始し、作業ディレクトリ・利用可能な操作・承認・キャンセル・再接続を実装する。既存のCLIを起動するだけのサイトにApp Serverを追加する必要はない。ホスティング、ストア審査、開発者アカウントを代行する仕組みではない。
